## Direction findings (not planned — options for the maintainer)

Surfaced by the audit with repo evidence; each would start as a design
spike, not a build-out. Ask for a plan if/when wanted:

- **A. Guide write path** — the human-guide-first read side is fully built
  (`guides` table, `Guide` schema, `/nearby` join) but nothing can create
  or edit a guide. One admin CRUD route + small panel closes the PRD's
  loudest loop ("success is measured partly by guide connections").
- **B. Human audio upload** — `ContentPieceInput` accepts `audioUrl` and
  `source: "human"`, and `putAudio()` abstracts storage, but only the AI
  pipeline can produce audio. Blocks the PRD's flagship "walk and record"
  story at step zero.
- **C. Route-segment triggers** — `ActivityMode` includes driving/transit/
  aviation and the PRD promises route drawing, but the geo model is
  point/polygon only; nothing linestring-shaped exists in schema or DDL.
- **D. Memory-palace mode** — a track type where spots are memorization
  *pegs* (method of loci), not subjects: you walk a familiar route and each
  spot speaks a fact you want to memorize, associated with what you're
  seeing there ("the oak by the gate — Magna Carta, 1215"). This inverts the
  content model: today a ContentPiece is *about* its place; here the place is
  an arbitrary anchor for unrelated content. Most machinery already exists —
  a Track of ordered Spots, GPS triggering, per-spot audio, the drive/walk
  simulator, and an AI pipeline that could generate vivid visual
  associations instead of location facts. What's new: (1) a track-level
  `kind` (`tour` | `palace`) or a per-spot content mode, since palace
  content must skip the location-anchoring + source-vetting that the tour
  pipeline enforces (a palace fact is deliberately *not* about the place);
  (2) an authoring flow to attach the fact list to a route and let the
  system assign facts to spots in walk order; (3) a recall/review loop
  (walk the route to memorize, then a test pass that prompts before
  speaking). Start as a design spike: decide track-`kind` vs. content-mode,
  and how the AI prompt flips from "narrate this place" to "invent a
  memorable image linking THIS place to THAT fact." Reuses `useDriveSim`,
  the trigger path, and `putAudio` nearly as-is. Note: this is additive to
  the PRD, not in it — flag for product sign-off before building.
